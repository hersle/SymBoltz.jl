\title{Chebyshev interpolation in \EB{} codes}
\authorrunning{Sletmoen, H.}
\author{Herman Sletmoen\thanks{Email: \texttt{herman.sletmoen@astro.uio.no}}}
\institute{Institute of Theoretical Astrophysics, University of Oslo, PO Box 1029 Blindern, 0315 Oslo, Norway}
\date{Received XX / Accepted XX}
\abstract{
	\EB{} codes compute theoretical predictions of cosmological models
	and rely heavily on interpolation in the independent variables:
	conformal time $\tau$, wavenumber $k$ and multipole $\ell$.
	We give a practical introduction to Chebyshev polynomial interpolation,
	which converges rapidly for smooth functions and thus synergizes with approximation-free codes.
	We show that interpolating in $k$ and $\ell$ with Chebyshev polynomials instead of traditional cubic splines
	results in higher precision from fewer solutions to the perturbations and line-of-sight integrals.
	On a set of example spectra for matter and the cosmic microwave background (CMB),
	we find $0$-$4$ orders of magnitude lower interpolation error using the same number of points
	(the exact improvement depends largely on the target function and is more dramatic at high precision levels).
	For a typical CMB temperature spectrum computed with interpolation in both $k$ and $\ell$,
	Chebyshev polynomials converge to $10^{-4}$-$10^{-5}$ relative error with only $50$-$80$ points per dimension,
	while cubic splines approach $10^{-4}$ error with $200$ points, which translates to a $2.5\times$-$4\times$ speedup.
	The $\ell$-interpolation needs line-of-sight integrals at non-integer $\ell$,
	but we also explain how it can be done by rounding Chebyshev nodes to their nearest integers at no performance loss.
	Chebyshev interpolation is implemented in SymBoltz (version 1.7),
	which is publicly available at \url{https://github.com/hersle/SymBoltz.jl}.
}

\section{Introduction}
\label{sec:intro}

\EB{} codes, such as SymBoltz \citep{sletmoenSymBoltzjlSymbolicnumericApproximationfree2026a}, CLASS \citep{blasCosmicLinearAnisotropy2011b} and CAMB \citep{lewisEfficientComputationCMB2000b},
are fundamental tools for computing theoretical predictions from cosmological models.
They solve large and stiff ordinary differential equations (ODEs) and many line-of-sight integrals of the background and perturbation equations.
This yields source functions $S(\tau)$ and $S(\tau, k)$ and transfer functions $\Delta_\ell(k)$
of conformal time $\tau$, perturbation wavenumber $k$ and angular multipole $\ell$.

Interpolation is one of the most effective optimizations in these codes.
Instead of evolving every $k$ and $\ell$ explicitly,
they do this only on coarse grids and then interpolate to more values.
This works because the output is smooth and saves time, but introduces interpolation errors.
Codes are tuned to balance performance and precision with default settings,
but they slow down significantly with finer precision parameters that sample more points.
Interpolation in cosmological parameters with polynomials or neural network \enquote{emulators} has received much attention in the literature
\citep[e.g.][]{fendtPicoParametersImpatient2007,albersCosmicNetPhysicsdrivenImplementation2019a,manciniCOSMOPOWEREmulatingCosmological2021,boniciCapsejlEfficientAutodifferentiable2024a},
but little has been given to interpolation in the independent variables $\tau$, $k$ and $\ell$.

Since the pioneering COSMICS code \citep{maCosmologicalPerturbationTheory1995},
interpolation has been done with cubic splines.
While solid for general-purpose interpolation,
they are outperformed by interpolation with Chebyshev polynomials \citep{trefethenApproximationTheoryApproximation2019}.
Cubic splines interpolate a function through $N$ points with $n=N-1$ piecewise cubic polynomials and an error that falls algebraically as $n^{-4}$.
In contrast, Chebyshev interpolation fits a single degree-$n$ polynomial through all points with an error that may drop exponentially as $\rho^{-n}$ for some $\rho$.
This interpolates with higher precision using fewer samples.
It is also simple to implement with the barycentric formula \citep{berrutBarycentricLagrangeInterpolation2004},
and unlike equispaced polynomial interpolation it is stable \citep{trefethenSixMythsPolynomial}.
%For example, Chebyshev approximation has popularized and shown to be very powerful by the Chebfun package in MATLAB \citep{battlesExtensionMATLABContinuous2004}.
However, the remarkably fast convergence depends on the function being smooth,
% (infinitely differentiable with bounded derivatives),
as is often true in physics.

Traditional \EB{} codes such as CAMB and CLASS use approximation schemes to switch between different equations at different $\tau$, $k$ and $\ell$ \citep[notably Figure 10]{blasCosmicLinearAnisotropy2011b}.
This is faster, but complicates both the physics and numerics.
Moreover, it breaks smoothness by introducing discontinuities or kinks at the switches.
Cubic splines are good for interpolating such functions because they join piecewise polynomials,
so changing one point affects the interpolant only locally.
Chebyshev interpolation instead uses global polynomials, and a fault in one point can slow convergence over the entire domain.

Recently, approximation-free \EB{} codes such as SymBoltz \citep{sletmoenSymBoltzjlSymbolicnumericApproximationfree2026a}, DISCO-EB \citep{hahnDISCODJDifferentiableEinsteinBoltzmann2024} and PyCosmo \citep{refregierPyCosmoIntegratedCosmological2018} have emerged.
They integrate the same equations at all times to obtain fully smooth solutions, but spend more effort per point.
In this paper, we show that approximation-free codes can leverage this smoothness with the rapid convergence of Chebyshev interpolation for performance and precision.
We implement this feature in SymBoltz\footnote{\url{https://hersle.github.io/SymBoltz.jl/}}.

\section{Computations in \EB{} codes}
\label{sec:sources}

The equations in \EB{} codes are solved in stages for $\tau$, $k$ and $\ell$,
each interpolating solutions of earlier stages.
Background functions $S(\tau)$ are interpolated in $\tau$;
perturbation sources $S(\tau, k)$ in $\tau$ and $k$;
and angular spectra $C_\ell$ in $\ell$ \citep[e.g.][]{callinHowCalculateCMB2006c}.

First, background and thermodynamics equations are solved for variables $S(\tau)$ that depend only on $\tau$.
For example, the Friedmann, continuity and Peebles equations are solved for the Hubble function $\scrH(\tau)$, free electron fraction $X_e(\tau)$, optical depth $\kappa(\tau)$, visibility function $v(\tau)$ and lookback time $\chi(\tau) = \tau_0 - \tau$.

Second, perturbation equations are solved for sources $S(\tau, k)$ by integrating large and stiff ODEs in $\tau$ for each independent $k$.
This interpolates the background solution in $\tau$.
For example, this provides sources for CMB temperature ($T$), polarization ($E$), lensing ($\psi$) and matter overdensity ($m$; see \cref{fig:sources}):
\begin{subequations}
	\begin{align}
		S^T    & = v \, \Bigg(\frac{\delta_\gamma}{4} + \Psi + \frac{\Pi_\gamma}{16}\Bigg) + e^{-\kappa} \, (\Psi + \Phi)^\prime + (v u_b)^\prime + \frac{3\big(v \Pi_\gamma\big)^{\prime\prime}}{16 k^2}, \\
		S^E    & = \frac{3 v \Pi_\gamma}{16 \, (k \chi)^2}, \\
		S^\psi & = (\Psi+\Phi) \, \frac{\chi_\text{rec}}{(\chi-\chi_\text{rec}) \chi} \, \theta(\tau - \taurec), \\
		S^m    & = \delta_m + 3 (1+w_m) \, \frac{\scrH}{k^2} \, \theta_m .
	\end{align}
	\label{eq:sources}%
\end{subequations}
%\Cref{fig:sources} shows these functions.
%This is usually the bottleneck.

Third, line-of-sight integrals
\citep{seljakLineofSightIntegrationApproach1996}%
\begin{equation}
    \Delta^A_\ell(k) = \int_{\tau_i}^{\tau_0} \diff{\tau} \, S^A(\tau, k) j_\ell(k \chi)
    \label{eq:los}
\end{equation}
are evaluated for a given source $S^A(\tau, k)$,
which must be interpolated in $\tau$ and $k$.
In turn, this is used to compute angular spectra%
\begin{equation}
    C_\ell^{AB} \propto \int_\kmin^\kmax \diff{k} \, k^2 P_0(k) \Delta^A_\ell(k) \Delta^B_\ell(k) \quad \text{(up to an $\ell$-scaling)}.
    \label{eq:spectra}
\end{equation}

Most $S(\tau, k)$ are smooth in $k$, but $j_\ell(k\chi)$ makes $\Delta_\ell(k)$ oscillate rapidly in $k$,
so the integrand of $C_\ell$ must be sampled at many $k$.
A standard trick is to solve the perturbations explicitly for only $10^2$-$10^3$ $k$-modes
and then interpolate $S(\tau, k)$ to $10^3$-$10^4$ values before line-of-sight integration.
This is $10\times$-$100\times$ faster than evolving the perturbations for all $k$,
as this bottlenecks the computation.

Most $C_\ell$ are also smooth in $\ell$,
so another standard trick is to line-of-sight integrate for some $\ell$,
and finally interpolate to every integer $\ell$.
This also leads to a significant speedup.

\section{Chebyshev polynomial interpolation}
\label{sec:chebyshev}

%Similarly to how Fourier series have extremely nice properties for interpolation of smooth functions that are periodic,
%interpolation with 

%Polynomial interpolation fits a single degree-$n$ polynomial through $N = n+1$ interpolation points,
%unlike (cubic) spline interpolation that joins $n$ piecewise (cubic) polynomials.
%This is perfectly stable and has very attractive properties for approximating smooth functions \emph{if} one uses Chebyshev polynomials.
%In contrast, interpolation with equispaced polynomials is unstable.
%In addition, Chebyshev interpolation is remarkably simple and efficient with Fast Fourier Transforms (FFTs) and the barycentric interpolation formula.
%Similarly to how Fourier series interpolation is optimal for interpolation of smooth periodic functions,
%Chebyshev polynomial interpolation is the closest analogue for near-optimal interpolation of an arbitrary smooth on a finite domain.

%We briefly summarize polynomial interpolation from the simplest possible practical angle, using the barycentric interpolation formula.
%As is common in the literature, we assume the domain is $x \in [-1, 1]$; otherwise it is trivial to linearly transform the domain before/after interpolation.

Any function $f(x)$ is interpolated through $N$ points $(x_i, f_i)$ by a polynomial $p_n(x)$ of order $n=N-1$:%
\begin{equation}
	f(x) \approx p_n(x) = \sum_j f_j \, \ell_j(x)
	\quad \text{with} \quad
	\ell_j(x) = \frac{\prod_{k \neq j} \, (x-x_k)}{\prod_{k \neq j} \, (x_j-x_k)} .
\label{eq:interppoly}
\end{equation}
The Lagrange polynomials satisfy $\ell_j(x_k) = \delta_{jk}$, so $p_n(x_k) = f_k$.
We work with the standard domain $x \in [-1, 1]$,
and map interpolation over arbitrary $y \in [a, b]$ with $x(y) = ( 2y-b-a ) / (b-a)$.

\iffalse
By convention, we here consider all points to lie on the canonical domain $x \in [-1, 1]$.
It is trivial to map points from an arbitrary domain $y \in [a, b]$ with the affine transformation
\begin{equation}
	y(x) = \frac{b+a}{2} + \frac{b-a}{2} x
	\  \iff \ 
	x(y) = \frac{2}{b-a} \, \bigg( y - \frac{b+a}{2} \bigg).
\end{equation}
\fi

The polynomial interpolation error is bounded by
%\citep{trefethenApproximationTheoryApproximation2019}
\begin{equation}
	\big\lvert f(x) - p_n(x) \big\rvert \leq \frac{M_{n+1}}{(n+1)!} \, \lvert \omega(x) \rvert,
	\quad
	\omega(x) = \prod_j (x-x_j),
\label{eq:error}
\end{equation}
where $M_{n} = \max \lvert f^{(n)}(x) \rvert$ on $x\in[-1,1]$.
Thus, the points should be placed in a way that minimizes the nodal polynomial $\lvert \omega(x) \rvert$.

Unintuitively, it is a bad idea to use uniformly spaced $x_j$.
Then $\omega(x)$ decays very slowly near the edges and is easily outrun by $M_{n+1}/(n+1)!$ as $n \rightarrow \infty$.
This leads to violent oscillations called Runge's phenomenon, as demonstrated in \cref{fig:recequi}.

Two particularly excellent ways to place the points are at the Chebyshev nodes of the first or second kind
\citep{trefethenApproximationTheoryApproximation2019}:
\begin{subequations}
\begin{align}
	x_m^{(1)} &= \cos \left( \frac{2m+1}{2n+2} \pi \right) \quad && (m = 0,\, 1,\, \ldots\, n), \label{eq:chebnodes1} \\
	x_m^{(2)} &= \cos \left( \frac{m}{n} \pi \right) \quad && (m = 0,\, 1,\, \ldots\, n). \label{eq:chebnodes2}
\end{align}
\label{eq:chebnodes}%
\end{subequations}
It is known that $x_m^{(1)}$ are the only points that bound $\lvert \omega(x) \rvert \leq 2^{-n}$ for all $x$.
Meanwhile, $x_m^{(2)}$ bound $\lvert \omega(x) \rvert \leq 2^{-n+1}$ but includes the endpoints $x = \pm 1$,
which is sometimes more or less practical.
In practice the two sets perform equally,
and other points with a similar $(1-x^2)^{-1/2}$ density profile are also effective.

The most attractive property of Chebyshev interpolation is that it converges faster the smoother $f(x)$ is \citep{trefethenSixMythsPolynomial}:
\begin{subequations}
\begin{align}
	\big\lvert f(x) - p_n(x) \big\rvert &\leq C \, \rho^{-n} \quad \text{if $f(x)$ is analytic,} \label{eq:geometric} \\
	\big\lvert f(x) - p_n(x) \big\rvert &\leq C \, n^{-\nu} \quad \text{if $f(x)$ is differentiable $\nu$ times.} \label{eq:algebraic}
\end{align}
\label{eq:convergence}%
\end{subequations}
This is called \enquote{geometric} and \enquote{algebraic} convergence, respectively.
Here $C$ and $\rho > 1$ are constants that depend on $f(x)$.
%The Chebyshev points are distributed with density $(1-x^2)^{-1/2}$ as $n \rightarrow \infty$,
%but polynomial interpolation is also effective using other points with a similar density profile.

\iffalse
The nicest property of Chebyshev interpolation
is seen when $f(x)$ is so smooth that its derivatives grow at most factorially.
Then $M_{n+1} \leq (n+1)! \, M_0$,
and the error \eqref{eq:error} falls exponentially:%
\begin{equation}
	\big\lvert f(x) - p_n(x) \big\rvert \leq 2^{-n} M_0.
	%\left\lvert f(x) - p_n(x) \right\rvert \leq C M_0 \, \rho^{-n}
	%\qquad \text{(for some $C$ and $\rho$).}
	%n \rightarrow \infty.
\label{eq:convergence}
\end{equation}

The simplest way to evaluate $p_n(x)$ is through the barycentric interpolation formula \citep{berrutBarycentricLagrangeInterpolation2004}:%
\begin{equation}
	p_n(x) = \sum_{j=0}^n \frac{w_j}{x-x_j} f_j \,\,\,\Bigg/\,\,\, \sum_{j=0}^n \frac{w_j}{x-x_j}.
\label{eq:bary}
\end{equation}
This involves the point-dependent interpolation weights
\begin{equation}
	w_j = \frac{1}{\omega^\prime(x_j)} = \frac{1}{\prod_{k \neq j} (x_j - x_k)}.
\label{eq:weights}
\end{equation}
They can be precomputed for a general scheme,
but for the Chebyshev nodes \eqref{eq:chebnodes} one can just use the analytical weights%
\begin{subequations}
\begin{align}
	w_j^{(1)} &= (-1)^j \sin \left( \frac{(2j+1)}{2n+2} \pi \right), \label{eq:chebweights1} \\
	w_j^{(2)} &= \begin{cases} (-1)^j/2 & \text{if } j = 0 \text{ or } j = n, \\ (-1)^j & \text{otherwise}. \end{cases} \label{eq:chebweights2}
\end{align}
\label{eq:chebweights}%
\end{subequations}
Barycentric interpolation is stable and uses only $O(n)$ operations per $x$.
Despite suspicious divisions by $x-x_j$, it is stable in floating point arithmetic even as $x \rightarrow x_j$,
and needs only a simple exception to return $f_j$ if $x = x_j$ exactly \citep{highamNumericalStabilityBarycentric2004}.
In contrast, the Lagrange form \eqref{eq:interppoly} is unstable and uses $O(n^2)$ operations per $x$.

\Cref{sec:coeffs} explains an optional way of checking
when $p_n(x)$ converges by expanding it in a series $p_n(x) = \sum_k a_k T_k(x)$ of Chebyshev polynomials $T_k(x)$
and inspecting the convergence of $\lvert a_k \rvert$ with $k$.
A Discrete Cosine Transform can compute the coefficients $a_k$ from the values $f_i$ with only $O(n \log n)$ operations.

\Cref{sec:tricks} describes some additional implementation details for using Chebyshev interpolation in practice.

In contrast, piecewise interpolation methods join low-order polynomials between each point and converge more slowly.
Linear interpolation is simplest with an error that drops as $n^{-2}$.
Cubic splines are smoother with an error that falls as $n^{-4}$.
They cause problems near the ends, where the spline assumes boundary conditions that need not match the function.
In return, splines are more stable for arbitrary point placements, are slightly faster, and respond better to localized imperfections in the data points.

Thus, Chebyshev interpolation is very attractive when:%
\begin{itemize}
\item $f(x)$ is known to be smooth, to get the fast convergence \eqref{eq:convergence};
\item $f(x)$ can be queried at any $x$, to match the points \eqref{eq:chebnodes};
\item $f(x)$ is expensive to evaluate, to benefit from fewer samples.
\end{itemize}
These conditions are seldom met when working with observed data, for example.
But they are often satisfied in theoretical applications, and particularly in \EB{} codes,
where the (unapproximated) underlying physics is smooth and the code is free to solve for any input.
In the next sections, we systematically consider interpolation in each of the three independent variables:
conformal time $\tau$, wavenumber $k$ and multipole $\ell$.

\section{Interpolation in time}
\label{sec:time}

We do \emph{not} use Chebyshev interpolation in $\tau$.
Nevertheless it is instructive to discuss why, to better understand the tradeoffs compared to Chebyshev interpolation in $k$ and $\ell$.

The background and perturbations for each $k$ are ODEs $u^\prime(\tau) = f(u, \tau)$ in $\tau$.
They have inherently local features,
as the universe undergoes eras dominated by radiation, matter and dark energy,
and shorter events such as recombination (see \cref{fig:sourceT}) and reionization.
The ODEs are solved by adaptive methods that automatically adjust their time step to capture the local features.
This conflicts with the rigid Chebyshev node placement \eqref{eq:chebnodes}.

Moreover, ODE solvers feature specialized dense output methods for interpolating over time steps.
They are usually custom-tailored to the solver in a way that maximizes accuracy while reusing internal calculations of $f(u, \tau)$ at intermediate steps taken by the solver.
SymBoltz defaults to the implicit Rodas5P ODE solver, which uses a specialized fourth-order interpolant \citep{steinebachConstructionRosenbrockWanner2023a}.
Even without specialized dense output,
the time derivative $u^\prime(\tau) = f(u, \tau)$ can be computed analytically \enquote{for free} from the solution $u(\tau)$ through the ODE definition.
One can then fall back to cubic Hermite interpolation,
which takes both $u(\tau)$ and $u^\prime(\tau)$ into account for accuracy.
We prefer the algorithm's built-in or natural interpolation method,
and use Chebyshev interpolation only when one does not exist.

%The combination of local features, adaptive time stepping and dense output methods of ODE solvers makes Chebyshev interpolation less suitable for $\tau$-interpolation.
%This also impacts performance less,
%as it is cheap to save more time points when integrating an ODE.
To take Chebyshev polynomials in time seriously,
one could try spectral ODE methods.
Instead of integrating $u(\tau)$ directly,
they expand $u(\tau) = \sum_k a_k T_k(\tau)$ in Chebyshev polynomials $T_k(\tau)$
and use the ODE to derive equations for $a_k$
\citep[e.g.][]{ranaSpectralChebyshevApproximation2025,choustikovOptimizingEvolutionPerturbations2023}.
This is outside the scope of this paper.

\section{Interpolation in wavenumber}
\label{sec:wavenumbers}

In $k$, however, Chebyshev interpolation is a good candidate.
The perturbation ODEs are independent for different $k$,
contain no analytical $k$-derivatives for Hermite interpolation,
and have a global nature in $k$ as the background affects all scales at a time $\tau$.

SymBoltz creates a \texttt{ChebyshevInterpolator} type from a wavenumber interval $[\kmin, \kmax]$ and a polynomial degree $n$.
It then maps the Chebyshev grid \eqref{eq:chebnodes2} to $[\kmin, \kmax]$ and solves the perturbation ODEs for every $k_j$ on the grid.
Afterwards, any source $S(\tau, k)$ is interpolated to any $k$ by evaluating the barycentric formula \eqref{eq:bary} with $f_j = S(\tau, k_j)$ and weights \eqref{eq:chebweights2} at fixed $\tau$.
A \texttt{PiecewiseChebyshevInterpolator} type is also available to perform Chebyshev interpolation on independent domains.

\Cref{fig:sources} shows the four test source functions \eqref{eq:sources} that we interpolate.
We interpolate $k \, S^T(\tau, k)$ and $k^2 \, S^E(\tau, k)$,
as they are smoother and of similar magnitude for fixed $\tau$ (see \cref{sec:tricks}).

It has no direct counterpart with splines.

\item

\section{Interpolation in multipole}
\label{sec:multipoles}

Angular power spectra $C_\ell$ are also smooth functions of the multipole $\ell$.
Instead of computing $C_\ell$ explicitly with line-of-sight integration for every $\ell$,
\EB{} codes do this only for some $\ell$ and then interpolate to all desired integer $\ell$.
This again makes Chebyshev interpolation a good candidate.

However, the discreteness of $\ell$ raises a difficulty.
As $C_\ell$ is physically interpreted only at integer $\ell$,
other codes interpolate from an integer $\ell$-grid (e.g. using every low $\ell$ and every $30$th high $\ell$).
This works with cubic splines because their stability is better for arbitrary grid configurations.
%Because the $\ell$-spacing is in steps of 1, CLASS relies on recursion relations in $\ell$ to evaluate the (hyper)spherical Bessel functions.
But it is incompatible with standard Chebyshev interpolation,
because the node placement \eqref{eq:chebnodes} forces the interpolation grid to both integer and non-integer $\ell$.
This was not a concern in \cref{sec:wavenumbers},
where sources vary continuously with $k$.
We show two different ways to solve this problem.

The first way is to proceed with standard Chebyshev interpolation,
but generalize the line-of-sight integrals \eqref{eq:los} and spherical Bessel functions $j_\ell(x)$ to arbitrary (integer and non-integer) $\ell$.
This is unproblematic from a physical point of view, as $j_\ell(x)$ is the solution that is regular at $x = 0$ of the ODE
\begin{equation}
	x^2 \frac{\mathrm{d}^2 j_\ell}{\mathrm{d} x^2} + 2x \frac{\mathrm{d} j_\ell}{\mathrm{d} x} + \left( x^2 - \ell(\ell+1) \right) j_\ell = 0.
	%\quad\!\!
	%j_\ell(0) = j_\ell^\prime(0) = 0.
\label{eq:besselode}
\end{equation}
This is well-defined and smooth in both $\ell$ and $x$, so interpolation from non-integer to integer $\ell$ converges.
The important part for interpolation is not the precise value of $j_\ell(x)$ for non-integer $\ell$;
only that there is a continuation of $j_\ell(x)$ between integer $\ell$ that is as smooth as possible.
Even cubic spline interpolation between integer-only $\ell$ relies on this property.%
\footnote{Extending $j_\ell(x)$ to continuous $\ell$ is analogous to analytically continuing the factorial $n!$ to the gamma function $\Gamma(n+1)$, for example.}
%Thus, the discreteness concern is only a conceptual subtlety,
%and practically it only means that $j_\ell(x)$ must be evaluated with $\ell$ treated as a continuous variable.%
SymBoltz uses the library Bessels.jl\footnote{\url{https://github.com/JuliaMath/Bessels.jl/}} to evaluate $j_\ell(x)$ at arbitrary $\ell$
when interpolating over $\ell \in [\ellmin, \ellmax]$ using a normal \texttt{ChebyshevInterpolator}.

The second solution is to evaluate $j_\ell(x)$ only at integer $\ell$,
but interpolate from Chebyshev points that are rounded to their closest integers.
Polynomial interpolation is reliable not only using the exact Chebyshev nodes \eqref{eq:chebnodes},
but from any points with a similar density profile.
Discreteness is also mitigated as the $\ell$-grid is quite fine-grained over 1000s of multipoles.
Note that the non-standard points break the Chebyshev weights \eqref{eq:chebweights} and coefficients \eqref{eq:coeffsdiscrete},
but barycentric interpolation is still straightforward using the general weights \eqref{eq:weights}.
SymBoltz creates an integer-rounded Chebyshev grid with a \texttt{ChebyshevIntegerInterpolator}.
It errors if the requested order is so high that multiple nodes round to the same integer.

%SymBoltz (version 1.7) enables both of these strategies.
%Line-of-sight integration is performed at non-integer $\ell$ by evaluating $j_\ell(x)$ at arbitrary $\ell$ with the library Bessels.jl\footnote{\url{https://github.com/JuliaMath/Bessels.jl/}}.
%Integer-rounded Chebyshev interpolation is offered by the \texttt{ChebyshevIntegerInterpolator} type.
%This enables Chebyshev interpolation, and also cubic spline interpolation without the integer-$\ell$ limitation.

\Cref{fig:cmb} compares $\ell$-interpolation performance of cubic splines versus Chebyshev polynomials.
To fix the computational cost, we restrain all methods to exactly 70 $\ell$-points.
For each method, we also require that the same $\ell$-grid interpolates all three spectra $C_\ell^\mathrm{TT}$, $C_\ell^\mathrm{EE}$ and $C_\ell^{\psi\psi}$, so the precomputed $j_\ell(x)$ is common.

For $C_\ell^\mathrm{TT}$ and $C_\ell^\mathrm{EE}$, Chebyshev interpolation converges to 3-4 orders of magnitude smaller error for $\ell \gtrsim 100$ than cubic splines.
For $C_\ell^\mathrm{\psi\psi}$, the cubic spline does better than a single Chebyshev polynomial.
This is because the Limber approximation switches on for $\ell \geq 10$ and makes a kink in $C_\ell$,
which disrupts the global polynomial and degrades it to algebraic $n^{-1}$-convergence \eqref{eq:algebraic}.
Cubic splines resist this because their behavior is local, so high $\ell$ is unaffected by the kink and they win with $n^{-4}$-convergence.
To fix this, we make a piecewise Chebyshev interpolant with two independent polynomials for $\ell \in [2, 10]$ and $\ell \in [10, 3000]$ (Limber approximation off and on).
This restores the performance of Chebyshev interpolation to the level of cubic splines.
%which is already excellent for $C_\ell^{\mathrm{\psi\psi}}$ because it is much smoother than $C_\ell^{\mathrm{TT}}$ and $C_\ell^{\mathrm{EE}}$.

Chebyshev interpolation is also simpler.
Fixing the computational cost to exactly 70 $\ell$-points,
we first tried a cubic spline with a uniform $\ell$-grid,
but this led to large interpolation errors for small $\ell$.
After progressively refining the $\ell$-grid with trial and error,
we ended up with a high-medium-low density $\ell$-grid over the subintervals of $\ell \in [2, 10, 100, 3000]$.
In contrast, Chebyshev interpolation performed better with a straightforward $\ell$-grid.

The figure also shows that integer-rounded and standard Chebyshev interpolation perform equally for $\ell$-interpolation.

Note that we have concentrated on a flat universe here,
as curved universes are not yet supported by SymBoltz.
In curved universes the spherical Bessel functions generalize to hyperspherical Bessel functions \citep[e.g.][]{lesgourguesFastAccurateCMB2014a}.
This modifies the ODE \eqref{eq:besselode} with an extra curvature-dependent term.
They are harder to compute, for example with recurrence relations between integer $\ell$ \citep{tramComputationHypersphericalBessel2017a}.
Particularly in closed universes, more restrictions are also placed on allowed integer values.
We anticipate that the integer-rounded Chebyshev interpolation strategy is easiest to generalize to curved geometries.

We conclude that Chebyshev polynomials are excellent also for $\ell$-interpolation.
They reach up to several orders of magnitude lower error in typical CMB temperature spectra compared to cubic splines with the same number of points.
It is also used in the emulator Capse.jl \citep{boniciCapsejlEfficientAutodifferentiable2024a} for $C_\ell(\theta)$ of cosmological parameters $\theta$.
However, there the main purpose is to train it on a smaller number of independent coefficients $a_n(\theta)$ in the Chebyshev expansion of $C_\ell(\theta) = \sum_n a_n(\theta) T_n(\ell)$,
instead of every $C_\ell(\theta)$.
%As a bonus, the coefficients $a_n(\theta)$ also accelerate the likelihood computation compared to $C_\ell(\theta)$ because it allows a significant part of the likelihood computation to be precomputed once.
This approach is related to ours, as FFTs can convert between $a_n$ and $C_\ell$ at the Chebyshev $\ell$-nodes (see \cref{sec:coeffs}).

\section{Conclusion}
\label{sec:conclusion}

We implemented interpolation with Chebyshev polynomials with the barycentric formula in SymBoltz,
by solving the perturbations and line-of-sight integrals at Chebyshev nodes in $k$ and $\ell$.
We showed that they interpolate with significantly lower error than traditional cubic splines using the same number of points.

The rapid convergence of Chebyshev interpolation for smooth functions forms a synergy with approximation-free \EB{} codes.
In contrast, approximation-based codes switch equations in $\tau$, $k$ and $\ell$ and solve each point faster,
which breaks smoothness and complicates the physics and numerics.
In other words, Chebyshev interpolation provides approximation-free codes a unique way to win back performance and precision.

%Approximation-based codes: speed up with approximations, less smooth and need more points at a great cost in modeling complexity.
%Approximation-free codes: more smooth and need more points, speed up by integrating fewer $k$-modes at no cost in modeling complexity.

Standard Chebyshev interpolation in $\ell$ requires line-of-sight integrals and spherical Bessel functions to be generalized to non-integer $\ell$,
but we showed how this can be avoided by rounding Chebyshev nodes to their nearest integer.
This performs comparably and would be easier to use in curved universes,
where hyperspherical Bessel functions are typically computed with integer-based polynomial and recurrence relations.

If implemented carefully, we speculate that approximation-based codes may also benefit from Chebyshev interpolation.
Due to its global nature,
imperfections in one point can slow interpolation convergence over the whole domain.
For example, we saw that the Limber approximation slowed convergence of Chebyshev $\ell$-interpolation,
but restored it by interpolating piecewise for $\ell < \ell_\text{Limber}$ and $\ell \geq \ell_\text{Limber}$.
The same strategy could be used for approximations in $k$-space,
but is not straightforward when the switching criterion varies with both $\tau$ and $k$.
Cubic splines are safer with approximations because their error decays locally and faster around non-smooth features,
but converge more slowly.

Finally, it must be said that interpolation is only one of many computational methods in \EB{} codes.
Our scope here was to study convergence only of interpolation,
while keeping other precision parameters fixed.
Of course, lower precision of line-of-sight quadrature, the Limber approximation and other methods may overshadow the high precision of Chebyshev interpolation.
Convergence with respect to all precision parameters calls for research into more high-precision methods,
such as better line-of-sight integration and beyond-Limber methods \citep[e.g.][]{schonebergTraditionalLineofSightApproach2018,fangLimberEfficientComputation2019,chiarenzaBLASTLimberAngular2024a}.

We believe Chebyshev interpolation is a step forward for simpler \EB{} codes
with numerical algorithms that make better use of the physical properties of the equations,
instead of resorting to complicated approximation schemes.

\section{Chebyshev coefficients}
\label{sec:coeffs}

Instead of interpolating with the barycentric formula in \cref{sec:chebyshev},
a function can be approximated with a series of Chebyshev polynomials.
This offers an alternative approach to Chebyshev interpolation that is particularly useful for error analysis.
We give a brief summary of this approach based on \cite{trefethenApproximationTheoryApproximation2019}.

\iffalse
\begin{figure}
	%\includegraphics[width=\linewidth]{figures/chebpoly.pdf}
    \includegraphics[width=\linewidth]{figures/chebpoints.pdf}
    \caption{%
        Chebyshev grids on $[\kmin, \kmax]$ with 2 to 80 points.
    }
\end{figure}
\fi

The Chebyshev polynomials of the first kind are defined as
\begin{equation}
	T_n(x) = \cos(n \arccos x)
	\quad \text{for} \quad
	%\theta(x) = \arccos x
	x \in [-1, 1].
\label{eq:chebpolydef}
\end{equation}
To see that $T_n(x)$ is a polynomial,
evaluate $T_0(x)$ and $T_1(x)$ explicitly and use the identities $\cos(n\theta\pm\theta) = \cos(n\theta) \cos(\theta) \mp \sin(n\theta) \sin(\theta)$ with $\theta = \arccos x$ to find the polynomial recurrence%
\begin{equation}
	T_0(x) = 1,
	\quad
	T_1(x) = x,
	\quad
	T_{n+1}(x) = 2 x T_n(x) - T_{n-1}(x).
\label{eq:recurrence}
\end{equation}
From the trigonometric definition, we see that $T_n(x) = 0$ when $n\theta = \frac{\pi}{2}(1+2m)$ for integer $m$, so its roots are the Chebyshev nodes of the first kind:
\begin{subequations}
\begin{equation}
	x_m = \cos \frac{\pi(1+2m)}{2n}
	\qquad (0 \leq m \leq n-1).
\label{eq:chebnodes1_app}
\end{equation}
Similarly, $\lvert T_n(x) \rvert = 1$ when $n\theta = m\pi$, so its extrema are the Chebyshev nodes of the second kind (including the endpoints $x = \pm 1$):
\begin{equation}
	x_m = \cos \frac{m\pi}{n}
	\qquad
	(0 \leq m \leq n).
\label{eq:chebnodes2_app}
\end{equation}
\end{subequations}
Both sets of points have the optimal density \eqref{eq:density} for robust polynomial interpolation.
As we will see soon, their $\cos$-dependence also opens the door to Fast Fourier Transform methods.

Chebyshev polynomials are an orthogonal basis for expanding a function $f(x)$ on $x \in [-1, 1]$ in a unique series%
\begin{equation}
	f(x) = \sum_{k=0}^\infty c_k T_k(x).
\label{eq:infseries}
\end{equation}
They are orthogonal with respect to the inner product
(change variables to $x = \cos \theta$ and use orthogonality of cosines)
\begin{equation}
	%\innerproduct{T_m(x)}{T_n(x)} =
	\frac{1}{\pi} \int_{-1}^1 \frac{T_m(x) T_n(x)}{\sqrt{1-x^2}} \, \diff{x} =
	\begin{cases} 0 & \text{if $m \neq n$,} \\ 1 & \text{if $m=n=0$,} \\ 1/2 & \text{if $m=n \geq 1$,} \end{cases}
\label{eq:innerprodcont}
\end{equation}
so the coefficients for representing a function $f(x)$ are
\begin{equation}
	%c_0 = \frac{1}{\pi} \int_{-1}^1 \frac{T_k(x) f(x)}{\sqrt{1-x^2}} \, \diff{x},
	%\qquad
	c_k = \frac{2}{\pi} \int_{-1}^1 \frac{T_k(x) f(x)}{\sqrt{1-x^2}} \, \diff{x},
\label{eq:coeffscont}
\end{equation}
and half of that for $c_0$.
These coefficients represent $f(x)$ in the infinite-dimensional space of \cref{eq:infseries}, and is not very practical.%

\subsection{Approximation with Chebyshev projection}

A more practical way to approximate $f(x)$ is to take the coefficients $c_k$,
but truncate the infinite series \eqref{eq:infseries} at a finite $n$:
\begin{equation}
	f(x) \approx \hat{p}_n(x) = \sum_{k=0}^n c_k T_k(x).
\label{eq:projection}
\end{equation}
This is called Chebyshev projection,
because dropping coefficients effectively projects $f(x)$ from an infinite-dimensional vector space down to a lower-dimensional polynomial space.
It requires $f(x)$ at arbitrary $x$ to compute the integrals \eqref{eq:coeffscont}.
%If the integrand is sampled at $n$ points, it amounts to $O(n^2)$ work to construct the approximation.
This method is sometimes appropriate when one has an expression for $f(x)$ and can evaluate the integrals analytically, for example.
However, it is impractical for interpolation purposes.

\subsection{Approximation with Chebyshev interpolation}

% https://www.buttenschoen.ca/MATH551/build/point-choice-4c36fbc36ea8e8d082339f77a23601f8.pdf
An even more practical method is to construct the polynomial $p_n(x)$ that passes through $f(x)$ at the Chebyshev nodes \eqref{eq:chebnodes2_app}.
Instead of using the barycentric formula in \cref{sec:chebyshev},
we can expand $p_n(x)$ in Chebyshev polynomials:
\begin{equation}
	f(x) \approx p_n(x) = \sum_{k=0}^n a_k T_k(x)
	\quad \text{such that} \quad
	p_n(x_m) = f(x_m).
\label{eq:interpolation}
\end{equation}
Analogously to the continuous inner product \eqref{eq:innerprodcont}, the Chebyshev polynomials also satisfy a discrete orthogonality relationship at the Chebyshev nodes \eqref{eq:chebnodes2_app}:
\begin{equation}
	%\innerproduct{T_i(x_k)}{T_j(x_k)} =
	\frac{1}{n} \sideset{}{''}\sum_{k=0}^n T_i(x_k) T_j(x_k) =
	\begin{cases} 0 & \text{if $i \neq j$,} \\ 1 & \text{if $i = j \in \{0, n\}$,} \\ 1/2 & \text{if $i = j \in [1,n-1]$,} \end{cases}
\label{eq:innerproddiscrete}
\end{equation}
where the double-primed sum means that the first and last terms are halved.
This means that the coefficients $a_k$ are picked out as
\begin{equation}
	a_k = \frac{2}{n} \sideset{}{''}\sum_{j=0}^n f(x_j) \cos \left( \frac{jk\pi}{n} \right) .
\label{eq:coeffsdiscrete}
\end{equation}
This is exactly a type-I Discrete Cosine Transform (DCT),
so the coefficients can be computed with only $O(n \log n)$ instead of $O(n^2)$ operations!
It is another reason for why Chebyshev points are particularly attractive for polynomial interpolation.
The DCT converts from the function values $f(x_j)$ of the barycentric approach to the coefficients $a_k$ of the series approach.

Once $a_k$ are known, the interpolating series \eqref{eq:interpolation} is easily computed for any $x$ with $O(n)$ operations.
A naive implementation is to iterate through every term while computing the recurrence \eqref{eq:recurrence} forwards, but this loses precision for $\lvert x \rvert \rightarrow 1$.
A stable and slightly faster way is to iterate backwards with the \cite{clenshawNoteSummationChebyshev1955} algorithm
with an intermediate variable $b_k(x)$:
\begin{subequations}
\begin{align}
	b_{n+1}(x) &= b_{n+2}(x) = 0, \\
	b_k(x) &= a_k + 2x b_{k+1}(x) - b_{k+2}(x) \quad \text{for $k = n, \ldots, 0$}, \\
	p_n(x) &= \textstyle{\frac12 \big(a_0 + b_0(x) - b_2(x)\big)}.
\end{align}
\end{subequations}

Interpolating with the Chebyshev series \eqref{eq:interpolation} instead of the barycentric formula \eqref{eq:bary}
is the method of choice when one wants the coefficients $a_k$.
They provide a useful diagnostic:
the neglected coefficients indicate the maximum interpolation error
\begin{equation}
	\max_{-1 \leq x \leq 1} \big\lvert f(x) - p_n(x) \big\rvert \leq \sum_{k=n+1}^\infty \lvert a_k \rvert,
\label{eq:coefferr}
\end{equation}
so convergence of $a_k$ implies convergence of the whole $p_n(x)$.

Chebyshev projection and Chebyshev interpolation are generally different methods with $\hat{p}_n(x) \neq p_n(x)$.
Their coefficients $c_k \neq a_k$ are related by aliasing formulas,
and they usually perform within a factor of 2 of each other \citep{trefethenApproximationTheoryApproximation2019}.
However, the latter is much more practical for interpolation from a finite set of points.

\section{Practical implementation details}
\label{sec:tricks}

To set up a Chebyshev interpolation object,
the user specifies the endpoints of the interpolation domain $x \in [a, b]$ and the polynomial degree $n$.
A grid $x_j$ of Chebyshev nodes \eqref{eq:chebnodes} is then created on $[-1, 1]$, and shifted and scaled to $[a, b]$.
To interpolate a function $f(x)$ at one or more point(s) $x \in [a, b]$,
we first evaluate $f_j = f(x_j)$ on all the grid points and then evaluate the barycentric formula \eqref{eq:bary}.

Sometimes it is better to interpolate not $f(x)$ directly,
but rather $f(x(y))$ where $x(y)$ is a domain transformation that maps $x$ to a different variable $y$.
For example, if $f(x)$ has more or less features in some areas,
a transformation of the domain can stretch out the features in busy areas and compress quiet areas.
Optionally, the user can provide a domain transformation $x(y)$ and its inverse $y(x)$.
The Chebyshev grid is then constructed in $y \in [y(a), y(b)]$ instead of $x \in [a, b]$,
and the barycentric formula is also evaluated in the variable $y$ instead of $x$.
By default the domain transformation is just the identity map $y(x) = x$ and $x(y) = y$,
which corresponds to no transformation.

Similarly, sometimes it is better to interpolate not $f(x)$ directly,
but rather apply a value transformation $g(f(x))$ first, interpolate $g$ and finally use $g^{-1}$ to recover $f$.
For example, this is useful if $f(x)$ spans many orders of magnitude and one wants to interpolate with minimal relative error,
as Chebyshev interpolation minimizes the absolute error \eqref{eq:error}.
One can then apply a $\log$-transformation or multiply $f(x)$ by some power law $x^n$ to make the target function of similar magnitude.
Our implementation permits this, and it can be combined with the domain transformation.

A final trick that we accommodate is piecewise Chebyshev interpolation.
This splits the interpolation domain $[a, b]$ into piecewise several domains $[a_i, b_i]$,
where we apply independent Chebyshev interpolations on each subdomain.
This is a useful alternative to the other strategies,
where one can use independent polynomials in different subdomains of the function,
for example if it spans different orders of magnitude or has more or less features in some areas.
This strategy is also vital if $f(x)$ has a discontinuity or kink at some point that breaks smoothness,
so we can interpolate with one polynomial before and another after the break point.

For example, we use these tricks to:
\begin{itemize}
\item Source functions: interpolate $k^n S(\tau, k)$ for some $n$ as a function of $k$.
\item Source functions that extend to very high $k$: interpolate $k^n S(\tau, k)$ as a function of $\arcsinh k/k_0$ for some linear-to-logarithmic transition scale $k_0$.
\item Matter power spectrum: interpolate $\log P(k)$ as a function of $\log k$.
\item CMB power spectrum: interpolate $\ell^5 C_\ell$ as a function of $\ell$.
\item Lensing power spectrum: interpolate piecewise before and after Limber.
\end{itemize}

These tricks are somewhat more important with Chebyshev interpolation than they are for cubic splines,
because of the fixed node placement \eqref{eq:chebnodes} and global behavior,
and that it is the \emph{absolute} error \eqref{eq:error} that is minimized,
so if the function spans several orders of magnitude the interpolation will heavily favor areas where the function is of large magnitude when measured in terms of the relative error.

To evaluate the Barycentric interpolation formula \eqref{eq:bary} for any $x$,
we loop over $j$, add $q_j = w_j / (x-x_j)$ and $q_j f_j$ to two cumulative variables for the denominator and numerator, and finally perform the division.
In every iteration, we also check if $x = x_j$ exactly and immediately return $f_j$ instead if that is the case.
As explained in \cref{sec:chebyshev}, this is stable for any $x$, also as $x \rightarrow x_j$.

\section{Implementation details}
\label{sec:implementation}

SymBoltz organizes different interpolation algorithms through a common \texttt{AbstractInterpolator} interface.
Several concrete methods are implemented, such as \texttt{LinearInterpolator}, \texttt{CubicSplineInterpolator} and \texttt{ChebyshevInterpolator}.
Each of them creates a grid of sample points $x_j$ as requested by the user's input,
and interpolates any function $f(x)$ to any $x$ using the corresponding method.
This interface makes it easy to switch the interpolation method anywhere in the code.

The \texttt{ChebyshevInterpolator} constructor takes an interval $[a, b]$ and a polynomial order $n$ as input.
It computes the Chebyshev nodes of the second kind \eqref{eq:chebnodes2} and transforms them to $[a, b]$.
To interpolate, the object is called with a list of function values $f_j = f(x_j)$ and a point $x$,
and then evaluates the barycentric quotient \eqref{eq:bary} with analytical weights \eqref{eq:chebweights2} after accumulating the numerator and denominator by looping over $j$.
At every iteration, it checks if $x = x_j$ exactly, and immediately returns $f_j$ if so.

The Chebyshev interpolation can be modified in a few ways.%

\subsection{Domain transformation}

Sometimes it is better to interpolate not $f(x)$ directly, but rather $f(x(y))$ where $y(x)$ is a domain transformation that maps $x$ to a different variable $y$.
For example, if $f(x)$ has more or less features in some areas, a transformation of the domain can stretch out the features in busy areas and compress quiet areas.
This is a useful technique with Chebyshev interpolation,
because it effectively makes the fixed node placement \eqref{eq:chebnodes} more flexible.

Optionally, \texttt{ChebyshevInterpolator} reads two keyword arguments $y$ and $y^{-1}$.
Interpolation is then done in $y \in [y(a), y(b)]$ instead of $x \in [a, b]$.
Corresponding $x$-points are found with $x_j = y^{-1}(y_j)$,
where $f(x)$ needs to be evaluated.
The function $y(x)$ should be chosen to make the composite function $f(x(y))$ as smooth as possible,
so Chebyshev interpolation works best.
%When the user asks for the interpolation to $x$,
%$y = f(x)$ is computed and the interpolation is done in $y$.

We currently use piecewise Chebyshev interpolation (see below) instead of domain transformation
to make the point placement more flexible.
For example, SymBoltz's default $k$-interpolator for spectra that include CMB lensing (\cref{sec:wavenumbers}) uses $y = f(k) = \tanh(k/k_0)$ with $k_0 = 2000$,
which compresses the interpolation domain to $y \in (-1,1)$ and concentrates nodes around the acoustic oscillations at $k \lesssim k_0$ while still reaching $k_\text{max} = 10^4$.

\subsection{Value transformation}

Similarly, sometimes it is better to interpolate not $f(x)$ directly,
but the transformed values $g(f(x))$ and use $g^{-1}$ to recover $f$ afterwards.
This is useful if $f(x)$ spans many orders of magnitude and one wants to interpolate with minimal relative error,
since Chebyshev interpolation minimizes the absolute error \eqref{eq:error}.
Applying a $\log$-transformation or multiplying $f(x)$ by a power law $x^n$ can bring the function to a more uniform magnitude over the interpolation domain.
This is handled by simply passing transformed $g(f(x_j))$-values to the interpolator.

This trick also combines with domain transformation,
so in general it is possible to interpolate $g(f(x(y)))$.

For example, we interpolate $k\,S^T$ and $k^2\,S^E$ in $k$ and $\ell^5\,C_\ell$ in $\ell$.
